**Every round must update `PROJECT_MAP.md` sections 3, 4 and 8 before stopping.**
**Every round must end with `tools\publish.bat` after `refresh.bat` and `secret_check`; PROJECT_MAP sections 3, 4, 7, 8 must be updated BEFORE publishing; a new Release is created only when a new BUILD is installed AND at least its checklist screenshots were reviewed by the supervisor.**

**Cloud review (CLOUD-PREP): private repo `KH3RM_AR_work` holds the EN+AR workspace for cloud Claude sessions (second pass of all dialogue and subtitles). Cloud sessions obey `CLOUD_RULES.md`, write corrections only to `review\corrections\cloud\<page>.tsv`, and never push to main. The public repo `KH3RM_AR` stays Arabic-only; 1.0.0 is LOCKED until (a) the cloud second-pass review is merged, (b) the image phase is done, (c) the user says go. Sync: `tools\sync_cloud.bat` (see `docs\CLOUD_WORKFLOW.md`).**

1. Run `tools\refresh.bat`; open `review\INDEX.md`, pick a category page in `review\md\` (300 rows per page). `review\FLAGS.md` lists only rows with validator flags.
2. Read EN (left) and AR (right). ERR flags must be fixed; WARN flags need a look.
3. Spelling/wording fixes go in a corrections file, never by editing the review pages:
   `review\corrections\<name>.tsv`, UTF-8, tab-separated, header `id<TAB>old_AR<TAB>new_AR<TAB>reason`.
   `id` = the 5-digit row id; `old_AR` = the current Arabic text exactly (empty if the row has none); `new_AR` = full corrected Arabic (tags and `{n}` kept); `reason` optional.
4. `tools\apply_corrections.py` (run by `tools\refresh.bat` before validate) checks every `old_AR` against the current text, refuses the whole run on any mismatch, otherwise writes `translation\<category>\<file>.tsv`, moves the file to `review\corrections\applied\` and appends `review\corrections\LOG.md`. Status: todo becomes translated, any other status is kept; set reviewed/verified by editing status separately.
5. Statuses: todo -> translated (draft) -> reviewed (spelling checked here) -> verified (seen in-game, entry in `state\SCREENSHOT_LOG.tsv`).
6. Rules: no harakat, no tatweel, Latin/Greek/Roman tokens only if they appear verbatim in the EN of the same row (LATIN policy, TRANS-2; `translation\allowed_latin.txt` is history only), tags/args/icons unchanged and in the same order, same line count (`<br>`), names as in the glossary (WARN GLOSS).
7. Screenshots (user decision, GLOSS-1): the user sends screenshots in the supervisor chat only and does not save them in `screenshots\`. Each one is still recorded in `state\SCREENSHOT_LOG.tsv` with `screenshot_file` = `chat` and `result` = the supervisor's verdict. (`screenshots\` stays as an optional, gitignored folder.)

## Glossary (GLOSS-1)
- Source of truth: `translation\glossary.tsv` (en, ar, type, source KH2/KH3-new/ReMind, status approved/proposed/pending, kh3_count, example_ids, note). `translation\glossary.md` and `translation\GLOSSARY_PROPOSALS.md` are generated by `tools\make_glossary.py` (run by `tools\refresh.bat`); never edit them by hand. Conflicts: `translation\GLOSSARY_CONFLICTS.md`. KH2 original: `translation\kh2_glossary.md` (reference only).
- Rule order for names: correct Arabic → English pronunciation for names → most common usage → shortest. Same English term = same Arabic everywhere. Only `approved` terms are used in bulk.
- Validator WARN GLOSS: an approved term (not type `menu`) appears in EN (as written or ALL CAPS, whole word) and its Arabic (leading ال optional) is missing from AR. One-word terms that KH3 EN also uses as ordinary lowercase words (will, even, pain…) are not checked.

### KH2 rules that do NOT apply to KH3
- Latin-letter bans and the KH2 safe-letter list (`M P W H A T S I`; `D`/`C` banned; no lowercase). KH3 policy (TRANS-2, final): every Latin/Roman/Greek token in AR must also appear verbatim in the EN of the same row (validator ERR LATIN). Keep as in EN: acronyms, brand names, rank letters, single-letter suffixes, sector codes, title numerals (KINGDOM HEARTS Ⅲ, II.9; words stay كينغدوم هارتس), Greek letters, URLs, Latin units. Exception: Arabic where it is clearly more natural and short and the EN is a plain word, or where the glossary approves an Arabic term (EXP, LV, EZ/PRO Codes).
- Arabic comma `،` is allowed and proven in-game** (TEST50 subtitle screenshot, 2026-10-09; supervisor decision TRANS-3, final): no space before it, one space after; ASCII `,` stays only inside numbers (5,000), Latin runs, tags/args/plural syntax. Arabic question mark `؟` is still ASCII `?` until a screenshot proves it.
- ya / alef-maqsura rule (`ى` → `ي`): not used.
- `<X 5E>` (KH2 atlas cell for XIII): does not exist in KH3. User decision GLOSS-2: Organization XIII = `منظمة XIII` (XIII as in EN), the Organization = `المنظمة`, Real Organization XIII = `منظمة XIII الحقيقية`.
- LV shortened to `مس`: not used. User decision GLOSS-2: LV / Lv. = `مستوى`, Next LV = `المستوى التالي`. Munny = `موني` in all forms (Munny Pouch = `كيس موني`; `مال` / `الموني` / `مميونة` retired). Olympus = `أوليمبوس` everywhere (never `أولمبيا`).
- Other shortenings made only for KH2 cell width were decided in TRANS-1/TRANS-2 (Journal = اليوميات, Full Bloom = الإزهار, Hollow Bastion = حصن هولو, Musical = موسيقي, Grind = طحن).
- Transliterations forced only by banned Latin letters (MCP `إم سي بي`, DTD `دي تي دي`, FPS Mode `منظور 1`, `فاينل فانتسي 3..10-2`, LT `الزر الأيسر`, `دوران 360`). These glossary entries are `pending` with note "...".
- KH2 tool specifics: `<C …>` state commands, FixState, atlas cells, the 150 % width WARN.

### KH2 rules that DO carry over
No harakat; no tatweel; tags, `{n}` args and icons kept exactly; same line count as EN; names as approved.
